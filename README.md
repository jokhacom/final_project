# Тренажер знаний ГЦО — архитектура проекта

**Обновление:** авторизация по логину/паролю, роли, ИИ-проверка по загруженным
материалам, Excel-экспорт и запрет копирования — теперь обязательные функции,
включены по умолчанию (не флагами на будущее, как было раньше).

## Обновление: база знаний ИИ (Topic → Rule → Question → Document)

Добавлено (расширение существующей схемы, без поломки старого функционала):

- **`Topic` и `Rule`** — ИИ читает документ и строит базу знаний: темы и
  конкретные правила (`REQUIRED`/`FORBIDDEN`/`RECOMMENDED`/`EXAMPLE_GOOD`/`EXAMPLE_BAD`).
  Эндпоинт: `POST /api/materials/[id]/extract-knowledge`.
- **Версии документов** — `Material.version`, `supersedesId`, `isActive`.
  Замена документа: `POST /api/materials/[id]/replace` — старые вопросы
  остаются привязаны к старой версии.
- **Question → Rule → Topic → Material** — вопрос теперь может ссылаться на
  конкретное правило (`topicId`, `ruleId`). Посмотреть цепочку источника:
  `GET /api/questions/[id]/source`. Генерация по правилу: `POST /api/questions/generate` с `ruleId`.
- **Удаление/перегенерация вопроса**: `DELETE /api/questions/[id]` и `POST /api/questions/[id]`.
- **Проверка ответов ссылается на конкретное правило**, если оно привязано к вопросу.
- **Страница `/admin/materials/[id]/knowledge`** — темы/правила + генерация вопросов по каждому.

Следующие этапы запроса: автогенерация программы по дням, новые типы заданий
(найди ошибку/исправь сообщение/выбери лучшее), AI-симулятор клиента,
геймификация (XP/уровни/streak), адаптивное обучение поверх `WeakTopic`.

## Первый запуск

1. `npx prisma migrate dev --name add-auth` — применить обновлённую схему (роли ADMIN, логин/пароль).
2. `npx prisma db seed` — создаст суперадминистратора с логином `javokhir` и
   **выведет временный пароль в консоль одним разом**. Запишите его сразу.
3. Войдите под этим логином/паролем и сразу смените пароль:
   ```
   POST /api/auth/change-password
   { "username": "javokhir", "currentPassword": "<временный из консоли>", "newPassword": "<ваш новый>" }
   ```
4. Обычные сотрудники регистрируются сами на главной странице (форма «Регистрация»),
   их роль всегда `EMPLOYEE`. Роль `ADMIN` можно выдать только вручную через БД
   (`UPDATE "User" SET role = 'ADMIN' WHERE username = '...'`).

## Что изменилось по каждому пункту запроса

1. **Авторизация** — `/` показывает вход/регистрацию по логину и паролю
   (`src/app/(public)/page.tsx`), пароли хранятся как bcrypt-хеш, данные не
   пропадают при перезапуске — это обычная запись в PostgreSQL.
2. **Роли** — `Role` enum: `EMPLOYEE`, `ADMIN`, `SUPERADMIN`. `/admin/*` защищён
   `src/middleware.ts` — туда не попадёт роль `EMPLOYEE`.
3. **Статистика и экспорт** — `GET /api/admin/export?userId=...&from=...&to=...`
   отдаёт настоящий `.xlsx` (через `exceljs`): лист сводки и лист по каждому
   ответу. Без `userId` — экспорт по всем сотрудникам.
4. **Случайные вопросы** — `/api/attempts/start` каждый раз выбирает новую
   случайную подвыборку из общей базы вопросов.
5. **ИИ-проверка по материалам** — `/api/grade` подтягивает из БД вопрос и текст
   материала, из которого он создан, и передаёт его в промпт с инструкцией
   проверять СТРОГО по этому тексту и объяснять решение.
6. **Запрет копирования** — `src/components/ProtectedTextarea.tsx`: блокирует
   copy/paste/cut, показывает предупреждение.
7. **Хранение данных** — всё через Prisma/PostgreSQL, ничего не теряется при перезапуске.
8. **Качество** — эндпоинты рабочие, не заглушки. Часть UI-страниц (сам процесс
   прохождения теста в этом Next.js-проекте) ещё требует вёрстки — API под них готово.

## Стек

- **Next.js (App Router)** — фронтенд + API routes в одном проекте
- **PostgreSQL + Prisma** — единая типизированная схема данных
- **NextAuth.js** — логин/пароль обязателен для всех
- **AI-провайдер за интерфейсом** — Claude сегодня, OpenAI или любой другой — завтра

## Ключевые точки расширения

### 1. Авторизация (сейчас выключена)

`src/lib/config/features.ts` → `AUTH_ENABLED = false`.

Пока флаг выключен: сотрудник вводит только имя, `User.email` и `User.passwordHash`
остаются `null`. Когда включите флаг:

- `src/lib/auth.ts` уже содержит настроенный `CredentialsProvider` — остаётся
  включить регистрацию/подтверждение почты (эндпоинты-заглушки уже созданы).
- Привязка старых данных к аккаунту: во всех таблицах (`TestAttempt`,
  `Achievement`, `LeaderboardEntry`) сотрудник определяется по `userId`,
  а `User` ищется/создаётся по имени ещё на первом этапе. Поэтому просто
  добавляете email/пароль к уже существующей записи `User` — история не теряется.

### 2. AI-провайдер (Claude сегодня, OpenAI — по желанию)

`src/lib/ai/provider.ts` — единый интерфейс:

```ts
interface AIProvider {
  generateQuestions(materialText: string, level: Level, count: number): Promise<Question[]>;
  gradeOpenAnswer(question: string, expected: string[], answer: string): Promise<GradeResult>;
}
```

- `src/lib/ai/anthropic.ts` — реализация на Claude (используется сейчас)
- `src/lib/ai/openai.ts` — заготовка реализации на OpenAI (заполнить ключ и промпт)
- `src/lib/ai/index.ts` — выбирает провайдера по `process.env.AI_PROVIDER` (`"anthropic" | "openai"`)

Чтобы подключить OpenAI: заполнить `openai.ts`, добавить `OPENAI_API_KEY` в `.env`,
поменять `AI_PROVIDER=openai`. Остальной код не меняется.

### 3. База знаний → генерация вопросов

- `POST /api/materials/upload` — загрузка PDF/DOCX/TXT (сейчас — заглушка,
  сохраняет файл и создаёт запись `Material` в БД со статусом `pending`)
- `POST /api/questions/generate` — берёт `Material`, вызывает
  `aiProvider.generateQuestions(...)`, сохраняет результат в таблицу `Question`
  с полем `sourceMaterialId` — так вопросы всегда прослеживаются до документа

### 4. Админ-панель

`src/app/(admin)/admin/*` — отдельная группа роутов. Доступ проверяется по
`User.role === "SUPERADMIN"` (единственная запись с этой ролью создаётся один раз
через seed-скрипт с email `mirkomilovjavohir562@gmail.com`, создание других
администраторов запрещено на уровне enum `Role`, у которого только два значения:
`EMPLOYEE` и `SUPERADMIN`).

### 5. История и данные сотрудников

Уже сейчас (этап 1, без авторизации) всё пишется в реальную БД, а не во временное
хранилище:

- `User` — создаётся при первом входе по имени
- `TestAttempt` — каждое прохождение теста/экзамена
- `Answer` — каждый ответ (вариант или открытый) с результатом проверки ИИ
- `Achievement` — разблокированные достижения
- `LeaderboardEntry` — материализованное представление для рейтинга (обновляется после каждой попытки)

Это значит: ответы **переживут закрытие сайта и перезапуск сервера**, в отличие
от демо-прототипа-артефакта, где использовалось временное хранилище Claude.

## Прямые ответы на вопросы

| Вопрос | Ответ |
|---|---|
| Сохранятся ли ответы после закрытия сайта? | Да — при этой архитектуре они пишутся в PostgreSQL сразу после каждого ответа/теста, не временно. |
| Будет ли настоящая база данных? | Да, PostgreSQL с полной схемой (`prisma/schema.prisma`), а не in-memory/temp-хранилище. |
| Можно ли подключить OpenAI для проверки открытых ответов? | Да, через `AIProvider`-интерфейс — добавляется как альтернативная реализация, переключается переменной окружения. |
| Будет ли код в GitHub? | Да, структура проекта сразу готова к пушу в репозиторий заказчика (см. `.gitignore`, `.env.example` — без секретов в коде). |

## Дальнейшие шаги разработки

1. Настроить БД (Docker Compose с Postgres или облачный сервис) и прогнать `prisma migrate`
2. Реализовать реальную загрузку файлов (`/api/materials/upload`) и парсинг PDF/DOCX
3. Реализовать `openai.ts`, если потребуется, как второй AI-провайдер
4. Включить `AUTH_ENABLED`, добавить страницы регистрации/подтверждения почты
5. Наполнить админ-панель UI (материалы, вопросы, статистика, обращения)
